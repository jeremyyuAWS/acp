# Remediate and Release clarity

The workflow presents saved outcomes before technical execution details. Assessment
capability categories remain context; live findings and publication receipts describe
what actually happened.

- A completed assessment introduces its remediation plan once. The introduction is
  remembered by assessment ID across navigation and reloads. Explicit Plan and Start
  actions remain available. Opening or closing the plan does not authorize execution.
- Accepted automation choices remain available in a compact disclosure. Existing
  standing AI approval gates continue to govern application; this UI change does not
  lower confidence, provenance, scope, or verification requirements.
- Document progress uses Processing, Verified, Needs attention, Ready to publish,
  and Published. Unknown evidence remains explicit. Finding counts and document
  counts have separate units; an approval or saved artifact does not prove resolution.
- Live category totals and document progress can filter the document list. Assessment
  Auto/AI/Manual totals are not decremented as a proxy for verified repairs.
- Activity is grouped by document. Genuine failures receive outcome colors and
  remain visible above routine milestones until superseded by successful delivery.
  Disabled or unavailable source mirroring is described as a copy saved in ACP.
  Zero recorded-change events are omitted rather than implying no automatic repairs.
- Release lists saved copies, selected-check verification, remaining work, and
  current delivery receipts. Delivery retries use the existing source, destination,
  and artifact checks and do not rerun remediation.
- The AI drawer begins with recorded outcomes. Its process navigator links analysis,
  generation, checking, approval, application, verification, and publication evidence.
  Unrecorded stage states and durations remain unavailable. Exact proposed values
  stay distinct from verified after values; model confidence is an estimate and is
  not verification proof. Model and recorded cost details follow the comparison.

Worktree UI verification uses Vitest DOM tests. The shared preview server is not
evidence about this branch. Entrance animations respect reduced-motion preferences.
