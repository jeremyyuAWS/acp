# Remediation and Release follow-up

Scope: the remaining confirmed gaps from the September 12 workflow review, rather than unrelated historical platform roadmap items.

- Release capacity belongs to the Remediate worker lane. The dashboard combines their queued demand before comparing it with measured shared capacity; it does not invent a separate Release pool or count the same slots twice. Worker labels say “Remediate & Release.”
- Automatic Excel description writes must preserve the matched drawing tag and authored escaped text. Real corrected workbook fixtures check XML readability, document preservation and detector outcomes.
- Review counts describe human input. Exact run/source-bound proposals admitted to an active automatic-check coordinator may appear in Processing as “Queued for automatic checks.” This is neither approval nor verified completion. Manual, failed, stale and unadmitted work stays actionable. A switch alone cannot prove a proposal eligible or a write complete.
- A new publication must reassess the exact Blob-backed corrected candidate with the canonical assessment path. Strict publication rejects remaining failures or uncertain assessment. Explicit remaining-issues publication retains the fresh evidence; it cannot omit approved writes or claim full compliance.
- Local downloaded-file audits compare exact hashes and explicitly supplied Office properties, while refusing ambiguous identities and malformed copies. They complement the provider canary rather than replace its placement/permissions/original-preservation checks.

The real customer SharePoint batch is not established by fixtures or deployment health. Its source/corrected files, recorded changes and release receipt must be identified and checked. This review has not automatically reprocessed or published historical customer files.
