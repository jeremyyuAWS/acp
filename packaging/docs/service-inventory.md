# ACP service inventory

What an ACP installation consists of, per deployment profile, derived from the shipped example
deployment documents. This is the reference an operator reads before sizing a cluster and the
one a reviewer reads to check that a platform adapter is not inventing services of its own.

Every table below is **generated**. To change one, change the contract or the example document it
comes from and re-run `python scripts/gen_service_inventory.py` — editing the table by hand makes
it disagree with the tool that deploys.

The authored half — why each profile exists, and what is supported versus preview — lives in
[ADR 0048](../../docs/adr/0048-portable-deployment-packaging.md) and in the PRD.

## Platform support

| Platform | Adapter supplies | Status |
|---|---|---|
| `aws` | EKS + RDS PostgreSQL, ElastiCache, S3, Secrets Manager | **planned** |
| `azure` | AKS + Azure Database for PostgreSQL, Azure Managed Redis, Blob Storage, Key Vault | **planned** |
| `compose` | single-server Docker Compose; embedded data services, evaluation only | **supported** |
| `gcp` | GKE + Cloud SQL PostgreSQL, Memorystore, Cloud Storage, Secret Manager | **planned** |
| `kubernetes` | customer-managed cluster; customer supplies Postgres, Redis, S3-compatible storage and a secret backend | **planned** |
| `onprem` | customer-managed cluster or single server; self-hosted data services throughout | **planned** |

`supported` means a reference deployment in this repository runs the contract suite against it. Everything else is `planned`.
