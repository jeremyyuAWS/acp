What this chart did NOT install, and what therefore has to already be true:

  * Postgres, Redis and object storage. Supplied by the platform adapter; this release reads
    their endpoints from the secret references below. See ADR 0048.
{{- if .Values.secrets.externalSecrets.enabled }}
  * The External Secrets Operator, and a SecretStore named
    "{{ .Values.secrets.externalSecrets.secretStoreRef | default (printf "%s-store" (include "acp.fullname" .)) }}" pointing at your {{ .Values.secrets.provider }} backend.
    Without it the ExternalSecret never syncs, the Secret is never created, and every pod stays
    in CreateContainerConfigError.
{{- end }}
{{- $needsKeda := false }}
{{- range $role, $cfg := .Values.workers }}{{ if and $cfg.autoscaling.enabled (eq ($cfg.autoscaling.scaler | default "keda") "keda") }}{{ $needsKeda = true }}{{ end }}{{ end }}
{{- if $needsKeda }}
  * KEDA. The worker ScaledObjects need it. WITHOUT KEDA THERE IS NO ERROR — the objects sit
    unreconciled, the workers stay at their minimum replica count, and the only symptom is a
    queue that grows during load and never scales out.
{{- end }}
{{- if .Values.networkPolicy.enabled }}
  * A CNI that enforces NetworkPolicy. Kubernetes accepts the objects either way; a CNI that
    does not implement them (Flannel, for one) leaves pod networking fully open with nothing
    reporting that the policies are inert.
{{- end }}
